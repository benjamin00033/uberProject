## 💡 關鍵架構決策 (Architectural Decisions)
1. **直屬獨立權限 (Direct Permissions) 與有效權限 (Effective Permissions) 職責分離**:
   - 在 DB 層面與 `/api/users` 列表/詳情 API 中，`permissions` 陣列僅代表使用者「額外直屬追加之細項權限」，不展開包含角色繼承之權限，從而完美支援前端 `UserModal.vue` 之 checkbox 勾選狀態預覽與編輯。
   - 在身分驗證 (JWT Token 與 `/api/auth/me`) 中，將角色預設權限與直屬權限取聯集生成 `effectivePermissions`，賦予守衛在授權驗證時享有完整的階層萬用字元比對能力。
2. **密碼空字串更新防覆蓋保護**:
   - 前端編輯彈窗傳入空字串密碼時，後端 Service 在更新前主動剔除 `password` 欄位，確保原密碼 Hash 不被覆寫為空值。
3. **自身帳號與 admin 超管帳號保護**:
   - `UserController` 在刪除前檢查當前登入者 ID，禁止刪除自身帳號；`UserService` 阻擋刪除 `admin` 使用者，防止系統成為無管理員孤兒狀態。
4. **Prisma 種子資料完備**:
   - 建立 `prisma/seed.ts` 並於 `package.json` 配置 `db:seed` 腳本，包含全系統 22 項權限字典、4 大角色及預設三名帳號 (admin, manager_chen, staff_lin)。
