## 💡 關鍵架構決策 (Architectural Decisions)
- **RESTful 通訊選型**：甘特圖拖曳雖然強調低延遲，但操作本質為狀態持久化保存 (`PATCH /api/tasks/:id/dates`)，採用 REST API 搭配輕量 Payload 與樂觀鎖檢驗，較 WebSocket 更加無狀態與易於快取控制。
- **Prisma Schema 關聯化與索引健全**：將原有扁平 mock 模型重構為包含 `ProjectMilestone` 與 `TaskAssignee` 複合主鍵之中介表模型，加入 `start_date, end_date` 區間複合索引與 `version` 樂觀鎖版本。
- **Provider/Repository 抽象解耦**：維持 `IProjectRepository`, `IMemberRepository`, `ITaskRepository`, `IHolidayRepository` 介面，使用 custom provider 動態注入 Prisma 實作，確保符合企業級 DDD 架構規範。
- **資料庫原子性樂觀鎖防護**：`PATCH /api/tasks/:id/dates` 透過 `updateMany({ where: { id, version } })` 實現在資料庫層級的一步比對與原子遞增，徹底消除並發拖曳競爭條件 (Race Condition)。
