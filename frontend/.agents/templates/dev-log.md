# Dev-log 範本

每日開發日誌。檔名格式：`YYYY-MM-DD.md`，例如 `2026-05-17.md`。
用途：未來 session（AI 或人）接手時，能 30 秒內看懂「昨天做到哪、為什麼、下一步」。

---

## 使用方式

- 一天一檔，commit / push 前更新（跟 AGENTS.md Git Workflow 對齊）
- **6 個固定區塊**，沒事可寫的區塊放「無」不要刪欄位（讓格式穩定，方便快速掃讀）
- 寫的是「為什麼這樣決定」跟「卡在哪」，不是 commit log 的逐字翻譯
- **AI 跟使用者的 Q&A 一定要記**：未來 session 才能回推「為什麼當時選 B 而不選 A 或 C」

---

## 範本骨架

```markdown
# YYYY-MM-DD

## 完成
- 做了什麼（一行描述 + 對應 commit hash 或 task 連結）
- 重點放「使用者 / 系統現在多了什麼能力」，不是「改了哪幾行」

## 進行中
- 開了頭但今天沒做完的事，含「卡在哪個步驟」
- 若無，寫「無」

## 詢問與裁決（AI ↔ 使用者）
- 記錄 AI 主動諮詢使用者的決策點，回推用
- 格式：
  - **Q**：AI 提出的問題 + 列出的選項 / 取捨
  - **A**：使用者的選擇 + 理由（理由比選擇本身更重要）
- 若無，寫「無」

## 決策 / 取捨
- 開發者自行做的非顯而易見選擇 + 為什麼（沒問 AI 也沒被 AI 問）
- 例：「為了避開 X 改用 Y，理由是 Z」
- 若無，寫「無」

## 卡點 / 待解
- 還沒想通、要查資料、要問人的事
- 若無，寫「無」

## 下一步
- 明天 / 下個 session 第一件事該做什麼
- 寫得越具體越好（「修 useOrderList 裡的 race condition」勝過「繼續做訂單模組」）
```

---

## 完整範例

```markdown
# 2026-05-17

## 完成
- 加上使用者大量匯入 CSV 預覽功能（commit `a1b2c3d`）
- `parseUserCsv` helper測試覆蓋到 100%
- 修掉 AGENTS.md 殘留的舊 stack 引用

## 進行中
- bulk-import 的 audit-log 寫入：server route 已串好，但批次失敗時的回滾還沒處理

## 詢問與裁決（AI ↔ 使用者）
- **Q**：批次失敗時要全部 rollback 還是允許部分寫入？
  - 選項 A：全部 rollback（保持原子性，但多 path 寫入無法真正原子）
  - 選項 B：允許部分寫入，失敗列回傳給前端讓使用者重試
  - 選項 C：全寫入，錯誤列存到 quarantine 節點等待人工處理
- **A**：選 B。理由：多 path 寫入在執行中失敗時 rollback 不可靠，假裝原子化反而誤導；讓使用者明確看到哪幾筆失敗、可逐筆修正後重送，更貼近實際操作習慣。

## 決策 / 取捨
- CSV 解析改在helper做（不接 file API），讓檔案讀取與解析分離，方便單元測試
- 不做範本下載功能，先讓使用者自己組 CSV — 之後若使用率高再加

## 卡點 / 待解
- 批次寫入上限？查到 multi-path update 一次 ≤ 1000 個 path，要不要拆批次？
- audit-log 應該「一次匯入一筆」還是「每個使用者一筆」？決策沒共識

## 下一步
- 找文件確認多路徑寫入上限，決定批次大小
- 寫 audit-log 粒度的 ADR，避免之後再改
```
